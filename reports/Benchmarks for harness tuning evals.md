# Mine eight benchmark slices where learning compounds

The first slice to take is **AppWorld's 60-task dev split**. It is one shared world of 9 apps and 457 APIs, installs with `pip`, grades by programmatic checks on database state, and is licensed for tuning. Published runs have already shown a learned playbook taking a mid-range open model (DeepSeek-V3.1) from a 42.4 average to 59.4, and to 57.2 with no labels, only execution feedback ([ACE](https://arxiv.org/html/2510.04618); [AppWorld](https://github.com/StonyBrookNLP/appworld)). Seven more slices cover the other kinds of work. **LAB-Bench SeqQA followed by CloningScenarios** is a science stream in which one sequence toolkit built early serves every later item. **KramaBench legal** (30 tasks over one messy 136-file data lake) is harder than the in-house data desk. **One SWE-Chain chain** (attrs, 13 steps) carries the agent's own code forward and grades it with hidden tests. **VerilogEval v2** is an engineering stream on a single simulator. **τ²-bench airline**, **Trainee-Bench Day 1→Day 2** and **cleaned optimisation-modelling sets** complete the list. Two things matter more than the benchmark's brand. First, only a handful of benchmarks carry state from task to task (SWE-Chain, SWE-Milestone, Sequential Gaia2, the Continual Learning Exam, Trainee-Bench). Most reset the world each task, so their payoff comes from knowing the world better, not from building on it. Second, the in-house evals have shown that idle-harness's improvement loop only earns its cost when feedback spans sessions and the stream is long, around 40 tasks. So the right slice keeps its grader outside the sandbox, runs at least 30–60 tasks on one shared thing, and sits where a cheap model eventually succeeds but at a cost that varies. No published score exists for xiaomi/mimo-v2.6-pro on any candidate. Benchmarks where frontier models score under about 25% (KramaBench, DABstep hard tasks, ReplicationBench, APEX-Agents, Hephaestus-CCX) risk giving it no approved solutions to learn from.

## Three questions sort the candidates before any domain does

The harness's own evals set the bar. On E20, a 40-question data desk over one orders CSV, every learning run beat frozen over the whole stream, improvement sessions included: **$0.79–$1.40 against $1.70**. Each improvement session cost $0.08–$0.24. Over the 15 questions of E16, the same loop did not pay for itself ([idle-harness evals](../idle-harness/evals/README.md)). E18 and E19 gave a sharper lesson: wherever a session can recover the truth by probing, the model closes that loop itself. The platform loop only matters for "a verdict that comes after the session has ended, a signal that only shows across many tasks" ([idle-harness evals](../idle-harness/evals/README.md)). E20 also shows the desk has saturated on quality, since every answer was right in the end. The next evals therefore need quality headroom as well as cost headroom.

Three questions follow from this, and they cut deeper than domain does. **Does anything carry from task to task?** A benchmark either carries state (the agent's code, files or app state persist), shares a world that resets each task, or shares only a toolchain. **Is the verdict hidden until the session ends?** Hidden tests and state checks run outside the sandbox suit the improvement loop. Visible unit tests let a session close its own loop. **Will a cheap model reach approval often enough?** Cost to an approved solution is undefined for a task never approved. A benchmark where frontier models score 40–70% gives a cheap model room to succeed slowly. One where they score 15% mostly yields failures. The continual-learning literature agrees: across Evo-Memory's streams, memory gains correlate with within-stream task similarity at **r = 0.717** (Gemini 2.5 Flash), and diverse sets such as AIME-25 and GPQA gain little ([Evo-Memory](https://arxiv.org/html/2511.20857v2)).

| Compounding tier | Benchmarks | What pays off later |
|---|---|---|
| State carries forward | SWE-Chain, SWE-Milestone, FeatureArc, Sequential Gaia2, CLE, Trainee-Bench Day 2, CodeClash | The agent's own artefacts, plus tools and notes |
| Shared world, reset per task | AppWorld, WorkBench, τ²-bench, EnterpriseOps-Gym, DABstep, KramaBench, DataBench, LiveSQLBench, BixBench capsules, ReplicationBench papers, SWE-Bench-CL | Knowledge of the world: API wrappers, schema notes, domain rules, profilers |
| Shared toolchain only | LAB-Bench SeqQA, VerilogEval, OR modelling, SpreadsheetBench, CAD-bench, Frontier-Eng, MLE-bench lite | Generic tools and procedures |

The middle tier is where E20 already lives, and it is the richest. The top tier tests what idle-harness is ultimately for, but it has few runnable releases.

## Data analysis already has an eval that works, so go harder

The data desk proved the mechanism. External data-analysis benchmarks are useful only if they add difficulty, messiness or a domain rulebook. **DataBench** (SemEval 2025) is the cheapest external replication. It has 80 real datasets and 1,822 closed-form questions (about 23 per dataset), MIT licence, and test answers now public ([DataBench](https://huggingface.co/datasets/cardiffnlp/databench)). Two datasets give a 45-question stream that the desk's exact-match scorer can grade. Most questions are single pandas expressions, though, so it would probably saturate like the desk. Its value is as a control showing that E20's result is not an artefact of a home-made CSV.

**KramaBench** is the real step up. It has 104 tasks and 633 subtasks over six domain data lakes. The legal lake holds **30 tasks over 136 small files (1.3 MB)** and the environment lake 20 tasks over 37 files (31 MB). It runs locally with `python evaluate.py --workload legal`, task JSONs carry `answer` fields, and `--skip_subtasks` drops the LLM-judged subtask scoring ([KramaBench](https://github.com/mitdbg/KramaBench)). A file catalogue, a per-source parser and notes on each source's quirks would be reused across all 30 tasks. That is the same pattern as E20's promoted `orders_query`, but under incomplete information. The risk is the floor: the best leaderboard result is **22.08%** (DS-GURU with o3), and the licence is unclear (the HF mirror says only "cc") ([KramaBench](https://github.com/mitdbg/KramaBench); [HF mirror](https://huggingface.co/datasets/eugenie-y/kramabench)). Run one cheap pass first, and use the slice only if mimo clears a meaningful share.

**DABstep** fits the harness better than anything else in this family. It has 450 tasks over one 24 MB context: a 138,000-row payments CSV, a fees JSON with over 1,000 rules, and a 22 kB domain manual. The tasks are expanded by parameterisation from about 95 core questions, 84% of them hard. Scoring is deterministic and CC-BY-4.0 ([DABstep paper](https://arxiv.org/html/2506.23719); [HF](https://huggingface.co/datasets/adyen/DABstep)). A fee-rule matcher built once would serve dozens of later tasks, and parameterisation means memorised answers do not transfer while procedures do. Grading is the obstacle. Only the 10 dev tasks have public answers. Reconstructing the rest from the public `submissions` and `task_scores` configs (about 1.04M rows) is plausible but unverified, and suitable only for private tuning ([HF](https://huggingface.co/datasets/adyen/DABstep)). The best hard-task accuracy is **14.55%** (o4-mini) ([DABstep paper](https://arxiv.org/html/2506.23719)), which puts it on the floor-risk list.

The SQL family is runnable but narrower. **LiveSQLBench Base-Lite-SQLite** has 270 tasks over 18 databases (about 15 per DB), each with a hierarchical knowledge base. Gold SQL comes only by email ([LiveSQLBench](https://github.com/bird-bench/livesqlbench)). **BIRD mini-dev** publishes SQLite gold for 500 pairs over 11 databases under CC BY-SA, but its tasks are one-shot text-to-SQL ([mini-dev](https://github.com/bird-bench/mini_dev)). **DAB** gives 13 realistic multi-database queries on crmarenapro, each with `ground_truth.csv` and `validate.py`. It needs PostgreSQL, MongoDB and Docker, and no licence was found ([DAB](https://github.com/ucbepic/DataAgentBench)). Three others are weaker fits. DSBench groups about 12 questions per ModelOff workbook, but its answers are judged by GPT-4o and the repo is non-commercial ([DSBench paper](https://arxiv.org/html/2409.07703); [repo](https://github.com/LiqiangJing/DSBench)). InfiAgent-DABench averages only 4.9 questions per CSV ([InfiAgent](https://arxiv.org/html/2401.05507)). DAComp's 50 DE-Evol tasks, which evolve existing pipelines, are conceptually ideal, but their engine and release were not verified ([DAComp](https://arxiv.org/html/2512.04324v1)).

## AppWorld leads the stateful app worlds; the carryover benchmarks are heavier

**AppWorld** is the strongest office/enterprise slice. It is one world of about 100 people across 9 apps, with 101 tables and about 370K rows. Tasks average 8–10 unique APIs and 42–47 calls, and they are graded by about 8 unit tests per task on the database diff, which also catch collateral damage ([AppWorld paper](https://arxiv.org/html/2407.18901)). Setup is `pip install appworld`, with Docker optional. Train (105) and dev (60) ship full ground truth and may be tuned on. The test splits (168 normal, 417 challenge) must not be inspected or tuned on ([AppWorld](https://github.com/StonyBrookNLP/appworld)). Each task loads its own copy of the base database, so state does not carry. What compounds is knowledge: login helpers, pagination wrappers, lookups through the people graph, and API quirks. ACE's evidence is direct. With DeepSeek-V3.1 and **no labels**, an online playbook updated after each test task scored 69.6 and 66.0, against a ReAct baseline averaging 42.4 ([ACE](https://arxiv.org/html/2510.04618)). Two cautions apply. The protected apps, tests and data ship as encrypted bundles that may only be redistributed encrypted. And the grader's ground truth must stay outside the sandbox profile ([AppWorld](https://github.com/StonyBrookNLP/appworld)), because E18 showed that an unsandboxed harness reads any answer key it can reach, 40–180 times per run ([idle-harness evals](../idle-harness/evals/README.md)).

**WorkBench** is the lightest alternative. It has 690 tasks over 5 sandbox databases and 26 tools, graded by comparing final state with ground truth. It installs with `uv sync` under MIT, and was re-evaluated across 24 models in 2026 ([paper](https://arxiv.org/abs/2405.00823); [repo](https://github.com/olly-styles/WorkBench)). **τ²-bench** airline (50 tasks) or retail (115) adds a policy document that a condensed checklist would serve well. But an LLM plays the user, adding about $0.059 per task at gpt-4.1 prices on top of $0.086 for the agent ([τ²-bench paper](https://arxiv.org/html/2506.07982)). Natural-language assertions are now judged by `gpt-5.4-mini`, and 2.0 scores are not comparable with 1.x ([tau2-bench](https://github.com/sierra-research/tau2-bench)). A cheap user simulator saves money at the cost of fidelity. **EnterpriseOps-Gym** has 181–186 tasks in each of ITSM, HR and CSM with SQL final-state verifiers. It needs one container per task run, the best model reaches 34.1%, and sources conflict on its licence ([HF README](https://huggingface.co/datasets/ServiceNow-AI/EnterpriseOps-Gym/blob/main/README.md)).

The benchmarks that genuinely carry state are heavier. **Trainee-Bench** runs 50 continual-learning scenarios over Day 1 and Day 2. Day 2 keeps the same task types with new parameters, checkpoints are rule-based, and the EvoEnv framework installs with `uv` without Docker. GPT-4o's checkpoint score *fell* from 0.42 to 0.36 between days ([Trainee-Bench](https://arxiv.org/html/2601.08173); [EvoEnv](https://github.com/KnowledgeXLab/EvoEnv)). That makes it a pointed test of whether Day 1 notes help. But the repo has 10 commits and no licence. **Sequential Gaia2** starts each scenario from the memory, conversation and app state the previous one left. It ships chains of 160 (search) and 95 (execution) scenarios across 10 universes, but only on "OpenClaw images" ([ARE](https://github.com/facebookresearch/meta-agents-research-environments)), so plugging in idle-harness means integration work. **The Continual Learning Exam** is the closest conceptual match of all. Its 120 five-level ladders reuse files, tools, preferences and rules from earlier levels, and a level passes only if every rubric item is met, much like an approval gate. The best of 17 configurations clears 47.7% of levels ([CLE](https://arxiv.org/abs/2610.33956)). CLE-Lite (20 tasks × 5 levels) needs Linux x86-64 Docker, a Codex login, at least 30 GB per task, and approval for the rubrics, though its judge can be DeepSeek V4 Flash via OpenRouter ([HF CLE-Lite](https://huggingface.co/datasets/Continual-Learning-Exam/CLE-Lite); [GitHub](https://github.com/haoyu-zhao/Continual-Learning-Exam)). It is a target for later, not a first slice.

Skip four groups. TheAgentCompany needs four services and 30+ GB ([repo](https://github.com/TheAgentCompany/TheAgentCompany)). WorkArena and CRMArena-Pro need remote ServiceNow or hosted Salesforce instances, and CRMArena-Pro is non-commercial ([WorkArena](https://github.com/ServiceNow/WorkArena); [CRMArena](https://github.com/SalesforceAIResearch/CRMArena)). OfficeBench and GDPval synthesise a fresh world per task, so little transfers ([OfficeBench](https://arxiv.org/html/2407.19056); [GDPval](https://huggingface.co/datasets/openai/gdpval)). APEX-Agents is judged by an LLM, and open models score under 5% on it ([APEX-Agents](https://arxiv.org/pdf/2601.14242)).

## Science and engineering reward a toolkit built once

These benchmarks rarely share a dataset. They do share a specialised toolchain, which is exactly where a promoted tool should pay off. **LAB-Bench** publishes **600 SeqQA and 33 CloningScenarios** multiple-choice items under CC-BY-SA-4.0 ([HF lab-bench](https://huggingface.co/datasets/futurehouse/lab-bench)). A stream of 30 SeqQA items followed by 8 cloning scenarios runs in pure Python with Biopython and has deterministic grading. A `seqtools` module (reverse complement, translation, ORF finding, digests, primer Tm, assembly simulation) built in the first ten tasks would be needed by every cloning task. It is the cleanest test of "tool built early, reused later". Two weaknesses: chance guessing blurs the quality rating, and the SeqQA sub-type labels needed to order the stream were not inspected.

**VerilogEval v2** gives 156 HDLBits problems graded by simulating against reference testbenches in Icarus Verilog. It needs Icarus v12 ("v13 is not supported"), Verilator and no Docker ([paper](https://arxiv.org/html/2408.11053); [repo](https://github.com/NVlabs/verilog-eval)). GPT-4o reached 65.1% spec-to-RTL in 2024, leaving a cheap model room to succeed slowly. A compile-and-simulate wrapper that summarises mismatches, plus notes on FSM and reset conventions, should compound across 30 problems taken in HDLBits order. HDLBits is old and public, so contamination is a real risk. **Optimisation modelling** is the cheapest engineering stream: PuLP or HiGHS, graded on objective value. Use only the cleaned sets (for example MAMO Complex 111, IndustryOR 42), because a 2025 survey found high error rates in the originals ([survey](https://arxiv.org/html/2508.10047v1); [sizes](https://arxiv.org/pdf/2605.02545)). Formulation patterns recur heavily, which suits a growing formulation library.

The design-iteration benchmarks best match "a design refined across tasks", but they are expensive. **CAD-bench** has 17 tasks "deliberately constructed to represent the progression of skills", from a cube up to gearboxes. Graders check dimensions, threads, mating and, for gearboxes, a Blender simulation. The best agent harness scores 67.7%, but agents average only 14.1% on the functional tier ([CAD-bench](https://cdn.jsdelivr.net/gh/CAD-bench/cad-bench@main/paper/main.pdf)). **Hephaestus-CCX** adds 50 FEA-checked briefs on CadQuery, gmsh and CalculiX. First-attempt strict passes are nearly zero, and GPT-5.5 with 10 attempts reached 9/50 strict passes at about 68 minutes per item ([Hephaestus-CCX](https://arxiv.org/html/2605.17448v2)). A cheap model would mostly fail it. **Frontier-Eng** offers 47 continuous-reward optimisation tasks, some CPU-only (truss FEM, battery models, JobShop). It also found that improvement decays roughly as 1/x and that **one deep chain beats many shallow chains** ([Frontier-Eng](https://arxiv.org/html/2604.12290v2)). That is an argument for running long streams rather than many short ones.

The shared-dataset science benchmarks either cost more or have hard floors. **BixBench** has 205 questions over 60 notebook capsules (1–7 per capsule) under Apache-2.0. It needs a Docker image or a local R/Bioconductor stack, its open answers are LLM-graded, and full runs take 24–48 hours ([BixBench](https://github.com/Future-House/BixBench); [HF](https://huggingface.co/datasets/futurehouse/BixBench)). **ReplicationBench** has 111 astrophysics tasks over 20 papers with recorded dependencies and tolerance-graded numeric answers, a genuine "builds on earlier tasks" design. It assumes a GPU per paper, and the best model scores 0.22 ([ReplicationBench](https://arxiv.org/html/2510.24591v2)). SciCode's main problems top out at 10.8% ([SciCode](https://github.com/scicode-bench/SciCode)). HAL declared CORE-Bench Hard solved after finding grading errors on 9 tasks ([HAL](https://hal.cs.princeton.edu/corebench_hard)). MLE-bench lite needs 158 GB and assumes a 24 GB GPU ([MLE-bench](https://github.com/openai/mle-bench)).

## Only chained code benchmarks carry the agent's own work forward

Coding is not the target, but it holds the only runnable benchmarks where later tasks start from the agent's earlier output. **SWE-Chain** chains release-to-release upgrades of Python packages: 12 chains, 155 transitions and 1,660 spec items. Each step is a fresh agent session in one persistent container, graded afterwards by hidden upstream tests, with "the original test suite ... explicitly removed" ([SWE-Chain](https://arxiv.org/html/2605.14415v1)). That loop matches idle-harness's working sessions in a shared project, and it puts the verdict after the session ends, the condition E18 and E19 identified. The attrs chain (13 steps) and the PyJWT chain (15) are small pure-Python packages. Code and data are Apache-2.0, and gold per-version results ship in `oracle/` ([GitHub](https://github.com/CUHK-ARISE/SWE-Chain); [HF](https://huggingface.co/datasets/mhlam/SWE-Chain)). Frontier configurations average 44.8% resolving and open-weight models fall behind on harder chains ([SWE-Chain](https://arxiv.org/html/2605.14415v1)), so track per-step resolving and regressions rather than whole-chain success. The runner is wired to Claude Code, Codex and OpenCode, so idle-harness needs its own scenario built from the JSONL specs. Whether a native venv can replace each chain's Dockerfile is unverified.

**SWE-Milestone** adds a dependency DAG across languages: navidrome has 9 milestones and ripgrep 11. It shows the cost of carrying defects forward. The best continuous score is **38.03%, against more than 80% on the same milestones run independently**. It needs about 115 DockerHub images and a bring-your-own-agent adapter ([SWE-Milestone](https://arxiv.org/html/2603.13428v3); [GitHub](https://github.com/DeepCommit-ai/SWE-Milestone)). FeatureArc, with no code released, found inherited defects in 72.9% of failed later stages, and agents left the earlier error unnoticed about 95% of the time ([FeatureArc](https://arxiv.org/abs/2610.37434)). In chained work, then, a harness-built regression runner is the tool most likely to pay off. **SWE-Bench-CL** is weaker than its name suggests. Each of its 273 tasks resets to its own base commit, patch overlap is low (mean Jaccard 0.111), and memory-on runs were on par with or worse than baseline ([SWE-Bench-CL](https://arxiv.org/html/2507.00014)). The underlying SWE-bench harness wants 120 GB of free disk ([SWE-bench](https://www.swebench.com/SWE-bench/guides/docker_setup/)).

## Continual-learning benchmarks say design the stream, then measure against yourself

The purpose-built continual-learning benchmarks converge on five lessons, and each maps onto an idle-harness scenario.

**Baselines.** Measure gain as the same system's stateful score minus its stateless score on the same instance, normalised by headroom ([CL-Bench](https://arxiv.org/html/2606.05661)). That is idle-harness's frozen structure. Add a plain full-history arm, because simple baselines keep winning. On CL-Bench, full-context ICL with Sonnet 4.6 ranked first, and ACE, at $62.8 per run, ranked ninth by gain ([CL-Bench](https://arxiv.org/html/2606.05661)). On MemoryAgentBench, long-context agents beat RAG and agentic memory ([MemoryAgentBench](https://arxiv.org/html/2507.05257v4)). On VibeMemBench, 11 of 12 pairings of a memory system with a solver failed to beat memory-off ([VibeMemBench](https://arxiv.org/abs/2609.23570)). The seeded structure serves as a ceiling.

**Ordering.** Run 3–5 orderings: CL-Bench uses 5 and StreamBench 5 seeds ([CL-Bench](https://arxiv.org/html/2606.05661); [StreamBench](https://arxiv.org/html/2406.08747v2)). Insert a deliberate shift mid-stream. CL-Bench swaps codebases, migrates a schema after 20 of 40 database questions, and returns to earlier poker opponents ([CL-Bench](https://arxiv.org/html/2606.05661)). Evo-Memory compares easy-to-hard against hard-to-easy ([Evo-Memory](https://arxiv.org/html/2511.20857v2)). AgentCL's **dependent streams**, where hidden subtasks precede the composite tasks among distractors, separated methods with a standard deviation of 14.9–16.0 against 2.3–5.7 for conventional streams. Yet only about 1% of stored episodes were relevant when a composite task arrived ([AgentCL](https://arxiv.org/html/2606.02461)). Ordering SeqQA basics before CloningScenarios, or AppWorld tasks by the apps they touch, is a cheap version of that.

**Stability and generalisation.** Add a second pass with frozen state, and a held-out set of unrelated tasks. AgentCL found that methods with large plasticity gains often had zero or negative stability and generalisation gains. On independent HumanEval-Pro tasks, memoryless ReAct scored best at 72.5% ([AgentCL](https://arxiv.org/html/2606.02461)). AppWorld's test-normal split, run once and never tuned on, is a ready-made held-out set.

**Leakage.** Feed back correctness or approval, never the answer. StreamBench found that storing incorrect self-outputs can push performance below zero-shot ([StreamBench](https://arxiv.org/html/2406.08747v2)). CLE returns only the unmet rubric categories ([HF CLE-Lite](https://huggingface.co/datasets/Continual-Learning-Exam/CLE-Lite)). SWE-Chain returns interface mismatches once ([SWE-Chain](https://arxiv.org/html/2605.14415v1)). In idle-harness terms, a reopen reason should name what failed, not what is right. AgentCL audits subtasks for leakage with token-set Jaccard against the parent, mean 0.10 ([AgentCL](https://arxiv.org/html/2606.02461)). E16 adds a harness-specific leak: an improvement session wrote verified answers into memory ([idle-harness evals](../idle-harness/evals/README.md)). That is harmless on a stream without repeats, but it inflates a frozen second pass and parameterised near-duplicates such as DABstep's.

**What memory helps.** Procedures beat answers. On AhaBench, worked procedures reached 80–100% held-out accuracy against 0–73.9% for question-plus-answer teaching ([AhaBench](https://arxiv.org/abs/2609.05435)). Retrieved, summarised prior experience cut tokens and runtime on SWE-ContextBench, while unfiltered context helped little or hurt ([SWE-ContextBench](https://arxiv.org/abs/2602.08316)). SkillLearnBench found that self-feedback alone causes "recursive drift" ([SkillLearnBench](https://arxiv.org/abs/2604.20087)). Smaller models benefit most from memory ([Evo-Memory](https://arxiv.org/html/2511.20857v2)). That favours the cheap-model setup, provided the stream is similar enough within itself.

## Ranked shortlist

Each slice becomes an idle-harness scenario. The benchmark's environment is copied fresh as the project, each task is one step, the benchmark grader runs outside the sandbox and drives `reopen` with a failure category, and `check` records cost to approval and the rating. Every slice runs frozen, layered and seeded where a seed is obvious, over at least three orderings.

## Conclusion

The search for "benchmarks that build on themselves" mostly turns up benchmarks that *share* a world but reset it each task. That is fine for idle-harness. E20 showed the loop pays off on exactly that shape once the stream is long enough, and ACE on AppWorld shows the same shape paying off on a stateful app world. The unproven claim is the other one: that promoted tools and memory help when later tasks inherit earlier artefacts and their defects. SWE-Chain is the only cheap, licensed, runnable test of it today, and FeatureArc and SWE-Milestone suggest the payoff there is a regression check, not more knowledge. So the shortlist pairs a breadth slice (AppWorld) with a carryover slice (SWE-Chain attrs). The science and engineering slices exist to show whether what improvement promotes generalises beyond data querying.

The binding constraint is the cheap model, not the benchmark. Every published number here comes from frontier or mid-tier models, and cost to approval means nothing for a task never approved. Before committing to any slice, run 5–10 of its tasks frozen with mimo-v2.6-pro and keep only slices where it reaches approval on a clear majority, with spread in cost. That pilot costs a few dollars. It decides whether KramaBench and the stretch list are evals at all or just ways to measure failure.
